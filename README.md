# 动量轮动信号系统

本地生成每日买卖信号，你在 Robinhood 手动执行。不接券商 API，不需要入金任何其他平台。

---

## 这套系统是什么，不是什么

**是**：一套规则明确、可回测、可证伪的趋势跟踪信号生成器。它的核心价值是**风险控制和执行纪律**，不是找到下一个十倍股。

**不是**：预测工具、荐股服务、赚钱保证。

每个组件都有明确的学术出处，不是拍脑袋调出来的：

| 组件 | 文献 | 作用 |
|---|---|---|
| 200日均线择时过滤 | Faber (2007) | **降低回撤，最关键的一块** |
| 12-1 横截面动量 | Jegadeesh & Titman (1993) | 选股 |
| 52周新高 | George & Hwang (2004) | 独立动量信号 |
| 波动率缩放 | Barroso & Santa-Clara (2015) | 防动量崩塌 |
| ATR 风险预算 | Van Tharp / Turtle | 仓位管理 |

## 快速开始

```bash
pip install -r requirements.txt

# 1. 先验证逻辑没问题 (合成数据，不需要网络)
python -m tests.test_logic

# 2. 跑真实数据回测
python -m core.backtest --start 2016-01-01 --stress

# 3. 检查是否过拟合 —— 这步不能跳过
python -m core.backtest --sweep

# 4. 生成今日信号
python run_daily.py --equity 10000
```

## 日常流程

```
美股收盘后 (英国时间约 21:00，全年基本不变——见下方说明)
    ↓
python run_daily.py --equity <你的账户权益>
    ↓
看报告：卖出指令 → 持有列表 → 买入指令
    ↓
去 Robinhood 执行
    ↓
每笔买入后立刻挂止损单 (Stop Loss)
    ↓
python record.py buy NVDA 12 178.40     ← 记账，这步不能省
python record.py sell AAPL 191.05
```

### 为什么记账不能省

程序无从得知你在 Robinhood 实际买了没有、买了多少、什么价格。移动止损依赖"持仓期最高价"，动量衰减判断依赖"我持有哪些票"。

**台账不准，系统就在用错误的状态给你出信号——比没有系统更危险。**

在 Robinhood 执行完的当天就记，不要拖。

### 关于收盘时间

纽约证券交易所收盘固定在美东时间 16:00。因为英美两国的夏令时基本同步切换（偏移都是 UTC-5/UTC-4 vs UTC+0/UTC+1，时差恒为 5 小时），换算成英国本地时间**全年都约等于 21:00**，不存在"夏天 21:05、冬天 22:05"这种整小时的季节性差异——只有每年 3 月和 10 月两国夏令时切换日期错开的那 1-2 周窗口期会短暂偏差 ±1 小时。定时任务按固定的英国本地时间（比如 21:15，留出安全余量）来跑即可，不需要按季节改时间。

## 买入规则（全部满足才买）

| 条件 | 阈值 | 理由 |
|---|---|---|
| **大盘 RISK-ON** | SPY > 200日均线 | **一票否决** |
| 动量分 | ≥ 90 | 全市场前 10% |
| 距52周高点 | ≥ 85% | 上方套牢盘少 |
| 均线排列 | P > EMA10 > EMA20 > EMA50 | 长中短期同向 |
| 扩张度 | < 3 ATR | **不追高** |
| 日均成交额 | ≥ $5M | 流动性 |

**仓位** = min(风险约束, 权重约束, 现金约束)

```
止损距离 = 2.5 × ATR20
风险约束 = 总权益 × 0.75% ÷ 止损距离
权重约束 = 总权益 × 20% ÷ 股价
```

最多同时持 8 只。买入信号每周五生成，下周一执行。

## 卖出规则（任一触发即卖，**每天检查**）

| 优先级 | 信号 | 含义 |
|---|---|---|
| 1 | SPY 跌破 200日均线 | **全部清仓**，不留例外 |
| 2 | 价格 ≤ 移动止损 | 自最高点回撤 3.5 ATR |
| 3 | 收盘跌破 EMA50 | 中期趋势破坏 |
| 4 | 动量分 < 40 | 已出强势区 |

**没有"再等等看"这一档。**

## 你必须提前知道的三件事

### 1. 胜率只有约三分之一

合成数据验证：**胜率 33.8%，盈亏比 1.67**。三笔里两笔亏钱是这套系统的正常形态，靠少数大赢覆盖多数小亏。

连续 4-5 次止损完全正常。那不是系统坏了，是市场没趋势。真正会杀死你的是在那个时候手动干预。

### 2. 择时过滤防崩盘，但防不住震荡市的钝刀子

测试里最大回撤是一段 **654 天的慢性失血**，不是崩盘。期间约一半时间空仓，反复被假突破扫出场。

这是这类系统的固有代价，不是缺陷。**实盘遇到横盘失血时最容易动摇——而那通常正好在反转前夜。**

### 3. 手动执行有真实成本

- **滑点和延迟**：系统假设按收盘价成交，你手动操作会隔几小时甚至一天
- **纪律风险**：每次止损都要你自己按下卖出键，人性会让你想"再等等"

回测里的 8bp 滑点假设对手动执行是乐观的。实际表现会低于回测。

## 已知局限（诚实清单）

- **幸存者偏差**：默认股票池是今天的大盘股，回测天然偏乐观。CAGR 至少打 2-3% 折扣看。
- **数据源**：yfinance 是非官方接口，Yahoo 随时可能限流或改动。长期跑建议换 Polygon.io / Tiingo。
- **未建模**：财报隔夜跳空击穿止损、停牌、分红税。
- **现金账户结算**：Robinhood 现金账户卖出资金 T+1 才可用，连续操作可能受限。
- **动量因子本身**：2004-2020 大部分时间里，扣掉成本后对散户是负的。这套系统的价值在于**把亏损控制在可承受范围**，不是超额收益。
- **回测的买入执行没有模拟"周五出信号、周一下单"的延迟**：`core/backtest.py` 在调仓日当天就以当日收盘价成交，而实盘是周一才能下单，中间隔了一个周末。8bp 的滑点假设不足以覆盖这个缺口，回测对买入端偏乐观。
- **`--stress` 压力测试段是从空仓现金重新起跑的**：例如 2020Q1 那段测的是"2月1日空仓开始交易"，不是"延续此前已建立的动量持仓，扛住 3 月的崩盘"。后者才是动量崩塌真正的风险场景，当前的压力测试方法论会低估它。

## 项目结构

```
core/
  config.py      所有参数 + 每个参数的理由
  universe.py    股票池 (含幸存者偏差说明)
  data.py        yfinance 下载 + parquet 缓存 + 质量检查
  signals.py     信号引擎 (面板向量化，含前视偏差防护)
  portfolio.py   本地持仓台账 (手动执行模式的核心)

tests/
  test_logic.py  56 项断言，改代码后必跑
```

## 自动化调度 (可选)

`run_daily.py` 跑完之后，如果配置了 Telegram，会自动把报告摘要 + HTML 存档推到你手机上。**执行仍然是手动的**——这只是省去"记得去跑一下"这一步，买卖本身还是你在 Robinhood 里做。

⚠️ 这台跑定时任务的机器必须能访问 Yahoo Finance 和 Telegram（有些沙箱/云端环境的出站网络会被限制），并且要保留 `data/` 目录不被清空——`data/positions.json` 是持仓状态的唯一来源，换机器或重装系统前先备份这个目录。

### 1. 配置 Telegram

1. 在 Telegram 里找 **@BotFather**，发 `/newbot`，按提示起名字，拿到一个形如 `123456:ABC-...` 的 token。
2. 找 **@userinfobot**（或任意"get my chat id"类的 bot），发一条消息，拿到你的数字 chat id。
3. 在项目根目录把 `.env.example` 复制成 `.env`，填入：
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-...
   TELEGRAM_CHAT_ID=123456789
   ```
4. 手动跑一次 `python run_daily.py --equity 10000` 确认能收到 Telegram 推送。不填 `.env` 也没关系——不影响报告正常生成，只是不推送。

### 2. Windows 任务计划程序 (Task Scheduler)

1. 开始菜单搜索"任务计划程序" (Task Scheduler)，选"创建基本任务"。
2. 触发器选"每天"，时间填 **21:15**（英国本地时间，见上文"关于收盘时间"——全年基本不用因夏令时改动；每年 3/10 月两国夏令时切换错开的那 1-2 周留了足够余量）。
3. 操作选"启动程序"：
   - 程序/脚本填 Python 解释器路径，比如 `C:\Users\<你>\AppData\Local\Programs\Python\Python311\python.exe`
   - 添加参数：`run_daily.py --equity 10000`（换成你的真实权益）
   - 起始于：项目根目录的完整路径，比如 `C:\Users\<你>\investing`
4. 在任务属性里勾选"不管用户是否登录都要运行"，并确认电脑在收盘时间不会休眠（电源选项里关掉自动睡眠，或换成"仅在接通电源时休眠"）。
5. 建好之后右键"运行"手动测试一次，确认能生成报告并收到 Telegram 推送。
